# EduFusion Agent 技术文档

## 一、项目概述

EduFusion Agent 是一个面向教师的**学科知识整合智能体**，能够自动解析多本教材（PDF/MD/TXT/DOCX）、构建跨教材知识图谱、语义去重压缩（≤原始体量30%）、提供带严格引用的RAG问答、支持教师自然语言反馈修改整合决策，并自动生成整合报告。

**技术栈：** FastAPI + React/TypeScript + ECharts + PyMuPDF + sentence-transformers + LLM API

**核心理念：** 确定性工作流 > 复杂多Agent协作。在5小时黑客松约束下，单编排器+工具代理架构是最优解。

| 维度 | 目标 |
|------|------|
| 教材解析 | 自动检测章节，支持4种格式 |
| 知识图谱 | 交互式ECharts力导向图，三重视觉编码 |
| 跨教材整合 | 语义去重，压缩比自动控制≤30% |
| RAG问答 | 混合检索+严格引用+Citation自检 |
| 教师反馈 | NL→结构化操作，5种意图识别 |
| 整合报告 | Markdown格式自动生成 |

## 二、系统架构

### 2.1 架构总览

```
┌─────────────────────────────────────────────────────────┐
│              Orchestrator (FastAPI 主控)                   │
│  请求路由 / 状态管理 / 流程编排 / CORS / 错误处理           │
└──────────────────────┬──────────────────────────────────┘
                       │
     ┌─────────┬───────┼───────┬──────────┬──────────┐
     ▼         ▼       ▼       ▼          ▼          ▼
  Parser    Extract  Graph   Integration  RAG    Chat Agent
  Agent     Agent    Builder  Agent       Agent  
  (PDF/     (LLM+    (图谱    (对齐+      (向量+   (NL意图
   MD/      规则     聚合+    去重+      关键词   解析+
   TXT/     抽取)    边重建)  压缩)      混合)    决策修改)
  DOCX)                         
```

### 2.2 为什么选择单编排器+工具代理架构？

| 维度 | 多Agent协作框架 | 单编排器+工具代理 |
|------|----------------|-------------------|
| 复杂度 | 高（通信协议、协调、冲突解决） | 低（确定性线性流程） |
| 可预测性 | 低（Agent行为不确定） | 高（有向无环工作流） |
| 调试难度 | 高（多节点交互追踪） | 低（单节点状态可观测） |
| 开发效率 | 低（框架学习+调参） | 高（直写业务逻辑） |
| **黑客松适配** | ❌ 5小时不够 | ✅ 快速闭环 |

**决策依据：** 教材整合的主流程是确定性的线性工作流（解析→抽取→建图→对齐→压缩→RAG→反馈），不需要Agent间自主协商。每个模块定义为Tool-Agent，保留Agent化能力的同时保持代码可控。

### 2.3 数据流

```
PDF/MD/TXT/DOCX → Parser → Chapters
    → Extraction (LLM主路径 / 规则降级) → KnowledgeNode[] + KnowledgeEdge[]
    → Graph Builder → 单本图谱JSON
    → Alignment (Embedding + Union-Find聚类) → MergeDecision[]
    → Compression (≤30%字数控制) → Merged Graph
    → RAG Indexer (滑动窗口分片 + 向量嵌入) → FAISS/numpy索引
    → RAG Query → top-K检索 → LLM答案生成 → 带引用响应
    → Chat (NL意图识别 → 决策修改 → 图谱更新)
    → Report (模板生成)
```

### 2.4 降级策略矩阵（5层）

| 代理 | 第1层（最优） | 第2层 | 第3层 | 第4层（兜底） |
|------|-------------|-------|-------|-------------|
| Extraction | LLM提取 | 规则提取 | 标题生成 | 空节点 |
| Alignment | sentence-transformers | difflib相似度 | 随机保留 | 全部keep |
| RAG | 向量+关键词混合 | 关键词检索 | 前N chunk | "不在知识库" |
| Chat | LLM解析 | 规则匹配 | 返回可选按钮 | 错误提示 |
| Report | LLM生成 | 模板填充 | 空报告 | - |

## 三、代理模块详解

### 3.1 Parser Agent（教材解析代理）

**输入：** PDF/MD/TXT/DOCX文件
**输出：** Textbook + Chapter[]（含章节结构、页码、字数）

**核心能力：**
- PyMuPDF逐页提取文本，保留页码元数据
- 正则章节检测（中英文标题格式）：`第X章` / `Chapter X` / `X.Y 标题`
- 虚拟章节回退：无章节结构时每10页生成虚拟章节
- DOCX支持：python-docx解析段落

**章节识别正则：**
```python
patterns = [
    r"第[一二三四五六七八九十百0-9]+章\s*[^\n]{0,40}",
    r"第[一二三四五六七八九十百0-9]+节\s*[^\n]{0,40}",
    r"Chapter\s+\d+[:：\s]?.*",
    r"^\d+(\.\d+)*\s+[^\n]{2,40}$"
]
```

### 3.2 Extraction Agent（知识抽取代理）

**输入：** Chapter内容
**输出：** KnowledgeNode[] + KnowledgeEdge[]

**核心能力：**
- LLM提取（主路径）：结构化Prompt，temperature=0.1，max_tokens=8000
- JSON修复：Pydantic校验失败→正则修复→规则兜底
- 每章最多10个节点、15条边
- 节点字段：id/name/definition/category/chapter/page/source_quote/frequency/confidence
- 关系类型：prerequisite（前置依赖）/ parallel（并列）/ contains（包含）/ applies_to（应用）

**Few-shot示例：** 已内置细胞生物学示例（细胞/细胞膜/线粒体），指导模型输出格式。

**降级路径：** LLM API → 规则提取（关键词+句式分析） → 从章节标题生成 → 返回空

### 3.3 Alignment Agent（对齐&整合代理）

**输入：** 多本教材的KnowledgeNode[] + KnowledgeEdge[]
**输出：** MergeDecision[] + Merged Graph + IntegrationStats

**核心算法：**
1. 文本归一化 → name+definition拼接
2. sentence-transformers计算embedding向量
3. 余弦相似度矩阵 → pairs
4. 分阈值处理：
   - ≥0.90 → 自动merge
   - 0.82-0.90 → LLM判断等价性
   - <0.82 → 保留为独立节点
5. Union-Find聚类合并等价节点
6. 合并节点选择：定义最完整+来源最多+连接度最高+频次最高
7. 边重建：所有边指向结果节点

**压缩控制：**
```
compression_ratio = compressed_chars / original_chars × 100%
goal: ≤ 30%
```

超过30%自动裁剪：删除低频remove节点 → 缩短定义 → 每个知识点只保留1条source_quote → 删除低重要性chunk

**重要性评分公式：**
```
importance = 0.35×frequency + 0.25×graph_degree + 0.20×chapter_weight + 0.20×citation_support
```

**教学完整性守卫（Teaching Integrity Guard）：**
- 教师明确要求保留的节点被删除 → -20分
- 前置依赖链上的高连接度源节点被删除 → -10分
- 高连接度节点（degree≥3）被删除 → -8分
- 高频节点（frequency≥2）被删除 → -5分
- 完整性评分<60分 → 触发警告，要求教师确认

### 3.4 RAG Agent（问答代理）

**输入：** 用户自然语言问题
**输出：** 答案 + Citation[] + CitationVerification[] + Benchmark指标

**检索管线：**

1. **分片（Chunking）：**
   - chunk_size=600字符（教科书段落自然边界）
   - overlap=80字符（边界信息不丢失）
   - 滑动窗口，非硬切割
   - 消融实验：300/600/1000对比，600最优（命中率100%，avg_score=0.81）

2. **混合检索：**
   - 向量检索：sentence-transformers编码→余弦相似度→Top-K*2
   - 关键词检索：正则提取中英文关键词→BM25-style词频评分→Top-K*2
   - 融合排序：`score = 0.7×vector_score + 0.3×keyword_score`
   - 合并去重→取Top-K

3. **LLM生成：**
   - 上下文约束："只能基于提供的片段回答"
   - 输出约束："只输出JSON"
   - 回答格式：answer + citations[{textbook, chapter, page, relevance_score, quote}]
   - 无匹配："当前知识库中未找到相关信息"
   - temperature=0.1

4. **Citation Guard（引用自检）：**
   - 每个citation验证：quote是否在source chunk中找到
   - 直接子串匹配 → 模糊匹配(SequenceMatcher > 0.6) → 元数据匹配
   - 输出verified标记："✅ 已验证" 或 "⚠️ 可疑" + 证据说明

5. **Benchmark输出：**
   - retrieval_method: hybrid/keyword
   - avg_score / max_score (检索相关度)
   - chunks_retrieved / total_chunks

### 3.5 Chat Agent（教师反馈代理）

**输入：** 自然语言指令
**输出：** 结构化操作 + 修改后的决策

**意图识别（规则优先，LLM兜底）：**

| 触发词 | Intent | 效果 |
|--------|--------|------|
| "为什么" | explain | 解释决策原因 |
| "保留" | keep | remove→keep |
| "删除" | remove | keep→remove |
| "合并" | merge | keep+keep→merge |
| "分开/拆开/不应该合并" | split | merge→keep×N |

**状态更新链：** 教师输入 → 意图解析 → 决策修改 → merged_graph重生成 → 前端刷新

### 3.6 Report Agent（报告代理）

**输入：** 整合状态（stats + decisions + graph）
**输出：** Markdown整合报告

**报告结构：**
1. 整合概览（教材数、原始字数、整合后字数、压缩比）
2. 整合决策摘要（merge/keep/remove数量）
3. 知识图谱统计（整合前后节点数、边数）
4. 重点整合案例（3-5个，含涉及教材、决策、理由、置信度）
5. 教学完整性说明（前置依赖保护、教师可恢复机制）

## 八、提示词工程

### 8.1 设计原则

1. **严格约束输出格式**：所有LLM调用要求只输出JSON
2. **上下文隔离**：每个任务独立的系统提示词模板文件
3. **Few-shot示例**：关键任务（知识抽取、合并判断）提供示例
4. **温度控制**：事实性任务temperature=0.1
5. **兜底机制**：JSON解析失败→正则修复→规则生成→Pydantic校验

### 8.2 提示词模板

```
backend/prompts/
├── extract_knowledge.txt  — 知识抽取（含few-shot细胞生物学示例）
├── merge_judge.txt        — 合并判断（含merge/keep各一个示例）
├── rag_answer.txt          — RAG答案生成（严格引用约束）
└── feedback_parse.txt      — 教师反馈意图解析
```

> 正文：细胞是生物体结构和功能的基本单位。细胞膜控制物质进出。线粒体是细胞的能量工厂。
>
> 输出：{"nodes":[{"id":"bio_ch01_n01","name":"细胞","definition":"生物体结构和功能的基本单位","category":"核心概念",...},{"id":"bio_ch01_n02","name":"细胞膜",...},{"id":"bio_ch01_n03","name":"线粒体",...}],"edges":[{"source":"bio_ch01_n01","target":"bio_ch01_n02","relation_type":"contains"},{"source":"bio_ch01_n01","target":"bio_ch01_n03","relation_type":"contains"}]}

## 十、已知局限与改进方向

| # | 局限 | 影响 | 改进方向 |
|---|------|------|---------|
| 1 | LLM每章15秒超时，长章节（>5000字）可能截断 | 尾部知识点遗漏 | 分段并行调用LLM |
| 2 | 规则降级时同义词识别精度低 | 无法加载LLM时知识点错分 | 引入HowNet同义词词典 |
| 3 | 内存状态不支持多Worker | 生产环境状态不一致 | 迁移Redis/SQLite |
| 4 | FAISS未启用（使用numpy dot product） | >5000 chunks时延迟增加 | 向量数>5000切换FAISS IndexFlatIP |
| 5 | 章节检测依赖正则 | 特殊格式漏检 | 增加更多模式或LLM辅助 |
